# 策略执行逻辑深度解耦与重构计划

## 1. 问题诊断 (Diagnosis)
经过分析 `App.tsx` 中的 `handleSendMessage` 逻辑，根本原因在于**策略应用的条件判断过于耦合了会话状态**：

*   **现状**:
    ```javascript
    // 只有在新会话且有 ticker 时才构建策略消息
    if (!activeConversationId && inputTicker && promptToUse) {
         messageContent = `Analyze ${inputTicker} using strategy: ${promptToUse.title}.`;
    }
    // 后续消息直接 push newMsg (纯文本)，完全忽略了 selectedPrompt
    ```
*   **后果**:
    1.  一旦 `activeConversationId` 存在（即第一条消息后），后续所有消息都被视为普通文本，不再应用策略模板。
    2.  UI 上的 Badge 逻辑 `const currentMode = (!activeConversationId && !ticker) ? 'initial' : 'followup';` 也是基于会话 ID，导致后续总是显示 "Free Chat"。

## 2. 架构重构方案 (Refactoring Architecture)

为了实现**"任何时刻、只要选中策略、发送消息即应用策略"**的目标，我们需要将策略执行从“新会话初始化”中解耦出来。

### 核心变更点：
1.  **策略上下文注入 (Strategy Context Injection)**:
    *   在每次 `handleSendMessage` 时，检查 `selectedPrompt`。
    *   如果有 `selectedPrompt`，则将用户输入包装在策略上下文中（例如：作为 `extra_context` 发送给后端，或者在前端构建 Prompt）。
    *   **关键决策**: 前端构建 Prompt 更灵活。逻辑改为：`User Input` + `Strategy Template` -> `LLM Input`。

2.  **状态模式修正 (Mode Logic)**:
    *   `currentMode` 不应只看 `activeConversationId`。
    *   **New Logic**: `currentMode = selectedPrompt ? 'strategy_exec' : 'free_chat'`。
    *   只要用户选中了策略，UI 就应该显示 "Running Strategy..."。

3.  **消息构建管道 (Message Pipeline)**:
    *   输入: `text` (用户输入), `selectedPrompt` (当前策略), `history` (历史消息)。
    *   处理:
        *   若 `selectedPrompt` 存在: 构建 `Analyze [Ticker/Text] using [Strategy]` 或更复杂的 Prompt 结构。
        *   若 `selectedPrompt` 为空: 保持原样 (Free Chat)。

## 3. 实施步骤

1.  **重构 `currentMode` (UI)**:
    *   修改 `App.tsx` 中的 `currentMode` 计算逻辑，使其响应 `selectedPrompt` 的状态。

2.  **重构 `handleSendMessage` (Logic)**:
    *   移除 `if (!activeConversationId ...)` 的限制。
    *   引入 `constructMessage(text, prompt)` 函数：
        *   如果 `prompt` 存在，返回 `Please analyze the following request using the '${prompt.title}' strategy framework: ${text}`。
        *   否则返回 `text`。
    *   确保每次发送都调用此构建函数。

3.  **后端兼容性**:
    *   目前的后端 `streamChat` 接受完整的 message history。只要前端构建好内容，后端无需修改即可支持“中途切换策略”。

## 4. 验证计划
*   **Case 1**: 新会话 -> 选策略 A -> 输入 "NVDA" -> **执行策略 A**。
*   **Case 2**: 继续对话 -> 保持策略 A -> 输入 "Risks?" -> **基于策略 A 的上下文回答** (或再次强调策略)。
*   **Case 3**: 继续对话 -> **切换到策略 B** -> 输入 "Valuation?" -> **执行策略 B** (System Prompt 可能会被新的 User Message 引导)。
*   **Case 4**: 继续对话 -> **取消选择策略** -> 输入 "Thanks" -> **Free Chat**。
