# 系统启动与对话功能优化计划

## 1. 统一启动脚本开发

为实现一键启动，我将编写一个 Windows 批处理脚本 (`start.bat`)，利用并行执行能力同时管理前后端进程。

*   **技术选型**: Windows Batch Script (针对当前 Windows 环境)
*   **功能实现**:
    *   **后端启动**: 激活 `uv` 虚拟环境 -> 启动 `uvicorn` 服务 -> 等待端口 8000 就绪。
    *   **前端启动**: 确保后端就绪后 -> 启动 `npm run dev`。
    *   **错误处理**: 捕捉启动失败的 exit code，并提示用户。
    *   **环境支持**: 通过 `SET ENV=dev` 或 `prod` 切换启动参数 (uvicorn reload vs workers)。

## 2. 历史对话与界面重构 (Frontend)

目前前端 `App.tsx` 仅实现了单次流式对话，**尚未实现历史记录列表和多轮对话管理**。需要进行较大规模的重构。

### 2.1 数据层重构
*   **API 集成**:
    *   `GET /api/conversations`: 获取左侧会话列表。
    *   `GET /api/conversations/{id}/messages`: 点击会话时加载历史消息。
*   **状态管理**:
    *   引入 `currentConversationId` 状态。
    *   将 `streamContent` 升级为 `messages` 数组 (`{role, content}[]`)，支持多轮对话渲染。

### 2.2 UI 布局重构 (Chat Layout)
*   **三栏布局**:
    1.  **Sidebar (Left)**: 历史会话列表 (支持滚动、搜索、点击切换)。
    2.  **Prompt/Config (Middle - 可折叠)**: 策略选择与 Ticker 配置 (保留现有功能)。
    3.  **Chat Window (Right/Main)**:
        *   **消息流**: 渲染 `user` (Prompt) 和 `assistant` (Markdown Report) 的气泡流。
        *   **滚动容器**: 自动滚动到底部 (Auto-scroll to bottom)。

### 2.3 功能实现细节
*   **多轮对话**: 每次生成新的分析报告时，不覆盖旧内容，而是 append 到 message 列表。
*   **持久化**: 依赖后端数据库存储，前端通过 API 拉取，实现刷新不丢失。
