# 彻底解决策略详情白屏问题

如果添加了可选链保护后仍然白屏，说明问题可能出在**正则表达式匹配**或**渲染逻辑**的深层缺陷上。

## 根本原因分析
当前的渲染逻辑使用了 `split` + `match` 的组合来高亮变量：
```javascript
selectedPrompt.text?.split(/(\$\{.*?\}|\[\[.*?\]\])/).map(...)
```
可能的问题点：
1.  **Regex 兼容性**: 某些浏览器可能不支持复杂的 Lookbehind 或特定的正则语法（尽管这里的正则比较标准）。
2.  **Key 唯一性**: `map` 中的 `key={i}` 在复杂渲染下可能不够稳定，虽然不至于导致白屏。
3.  **数据类型**: 后端返回的 `text` 可能不是 `string`，而是 `null` 或其他类型，导致 `split` 方法根本不存在。
4.  **死循环**: 如果正则匹配导致生成了无限数组（极低概率）。

## 最佳实践方案：简化渲染逻辑

为了彻底杜绝白屏，建议放弃这种“在渲染时实时拆分高亮”的脆弱逻辑，改用更健壮的 **Markdown 渲染** 或 **预处理** 方式。

考虑到您需要高亮 `${var}`，我们可以采用以下方案：

### 方案 A: 预处理高亮 (Recommended)
编写一个独立的工具函数 `formatPromptText(text)`，它负责安全地解析文本并返回一个包含样式信息的对象数组。
*   **优势**: 逻辑从 JSX 中分离，易于调试和错误捕获 (Try-Catch)。
*   **安全**: 如果解析失败，直接返回原始文本，绝不崩溃。

### 方案 B: 纯 CSS 高亮 (Simpler)
将 Prompt 内容放入 `<pre>` 标签，利用 CSS 的 `highlight` 伪元素（浏览器支持度一般）或简单的文本替换。

### 决定：实施方案 A + 错误边界 (Error Boundary)

1.  **添加 Error Boundary**: 在 `App.tsx` 中为 `StrategyDetail` 区域包裹一个错误边界，确保即使这部分崩溃，也不会拖累整个应用。
2.  **重构渲染函数**: 提取 `renderPromptContent` 函数，内部包含完整的 `try-catch` 和类型检查。
3.  **后端数据核查**: 确认后端返回的 `Prompt` 对象结构。

## 执行步骤
1.  **后端检查**: 确认 `Prompt` 模型定义。
2.  **前端重构**:
    *   在 `App.tsx` 中创建 `SafeStrategyPreview` 组件。
    *   使用 `try-catch` 保护渲染逻辑。
    *   增加对 `text` 的严格类型检查 (`typeof text !== 'string'`).
